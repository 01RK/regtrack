# 工作组会议 Excel 导入

入口：工作组会议右上角「导入会议纪要」，或单场会议的「导入纪要」。

## 四步向导

页面每次只显示一个步骤，可以返回修改选择。

1. **上传 Excel**：下载空白模板和提示词，把原始材料与模板一起交给大模型。上传生成的 `.xlsx`，校验通过后点击下一步。自动解析入口仅预留，当前不可用。
2. **确认会议**：核对标题和日期，选择标题相似度至少70%的最多3场候选，或同日会议（合并去重），或明确新建会议。同日同名会议不重复新建。议题及结论可展开查看。
3. **选择追踪标准**：每项标准使用紧凑行布局，左侧名称、右侧追踪选择，纪要默认折叠。确认匹配已有主档即追踪；无匹配的标准可新建主档并追踪，或不追踪（不入库）。新建时确认名称，标准号可留空；同类预留编号可用于多个主档。已归档候选先恢复才能关联。
4. **核对并导入**：同时展示当前会议已有事项和本次可导入事项；同标题新事项默认标记为不导入，可删除或恢复新旧任意条目。删除显示灰色和删除线，提示最终删除/保留数量，确认前不写库。返回修改追踪范围后重新计算事项，原确认勾选失效。最终确认才一次提交。

## Excel 模板

下载文件：`static/meeting-import-template.xlsx`。

只包含 `Meeting`、`Standards`、`Actions` 三张工作表。第1行是固定英文表头，第2行是中文字段说明，第3行起填写数据。Meeting必须且只能有一条会议；另外两表各最多300条，无数据则留空。最大2 MB，不含图片或公式。日期接受Excel日期值或YYYY-MM-DD文本。

| 工作表 | 字段 |
| --- | --- |
| Meeting | Meeting Title、Meeting Date、Key Discussions、Overall Conclusion、Organizer |
| Standards | Standard Key、Standard Name、Standard No.、Minutes |
| Actions | Action Title、Description、Standard Keys、Owner、Due Date |

标准Key是文件内部唯一标识，如S1，不是数据库ID。多标准事项用英文逗号关联，例如 `S2,S3`。只有真正独立于标准的会议事务才将Standard Keys留空，不能将共同标准事项伪装成整体会议事务。有实际编号时保留；未编号但类型明确时按 GB XXXX、GB/T XXXX、QC/T XXXX、ISO XXXX 等形式填写，类型无法判断时留空。标准主档以ID关联，空号和含XXXX的预留编号可重复，正式编号仍唯一。提示词要求直接描述纪要与事项，不附来源页码、缺失说明或占位号解释。

旧JSON上传方式和模板已移除。

## 纪要与事项规则

- 匹配现有会议时保留原标题和日期，追加议题、结论；组织方仅补空值。标准Note保留原有人工内容并追加新纪要，相同段落不重复追加。
- 不追踪标准不建主档、不保存纪要、不挂载会议，其专属事项不入库，不创建状态历史或人员字典。已移除 meeting_reference 表及显示、交换路径。
- 多标准共同事项：至少一个关联标准被追踪才导入；所有关联标准均不追踪则过滤。只追踪一个标准时关联该主档，追踪多个时作为会议共同事项保存，原文关联身份保留在说明中。
- 真正独立的会议整体事项可以导入。事项创建为Others / Open，保留负责人、截止日及初始状态历史。
- 事项标题相似度至少70%时标记可能重复，同标题的新事项默认不导入，用户可恢复并确认同时保留。服务端只新增明确保留的新事项，删除明确排除的已有事项及其状态历史、反馈记录。已有事项核对后发生变化时拒绝提交，要求重新核对。全部操作在同一事务内，任意失败回滚。
- 后续再次导入并选择追踪时，可建档/匹配，并导入此前被排除的分标准纪要和事项。

## 数据和验证

默认数据库仍为 `data/regtrack-v0.19-fix3.db`，schema已移除未追踪纪要表，模拟数据同步移除仅纪要示例。

`docs/meeting-import-example.xlsx` 根据 `ref_metg_material` 两份材料整理：1场会议、4项标准、5条事项。会议日期为2026-07-15。未编号的两个分部分填 GB/T XXXX.1、GB/T XXXX.2，示例纪要只包含讨论内容。

示例中只追踪GB/T 31484时，导入3条事项，另外2条不显示、不入库；四项标准都不追踪时，5条事项全部过滤。系列草案更新关联S2,S3，不能使用空关联绕过过滤。

在 `regtrack/codes` 运行 `python -m unittest test_meeting_import -v`。测试覆盖Excel读取、日期、错误表头/公式/关联、旧JSON拒绝、过滤、共享事项、空列表、匹配、回滚、重复导入的新旧事项核对、删除/恢复范围、变更拒绝、重新追踪及数据交换。

Edge浏览器验证了步骤隔离、Excel上传、前进/返回、追踪范围修改后事项重算、重新确认、3条保存/2条过滤和390px窄屏布局。Excel模板与示例的三张表均已渲染检查，并重新读取验证。
