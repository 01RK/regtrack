# 两版本评价与融合取舍

评价在修改前已向用户说明；这里保留实施依据。

| 方面 | 6.1sol | 5.5opus | 融合决定 |
|---|---|---|---|
| 部署 | 中心 Waitress 服务、环境变量、有界连接池 | 每位同事运行应用并直连 PG/S3 | 采用 sol；新增 Linux systemd 与 Caddy |
| 主要业务 | 标准、草案、意见、比对、会议、事项与采集 | 主要逻辑与 sol 高度一致 | 保留原功能，不重复拼接 |
| 文件持久化 | PG 元数据 + 随机对象名；事务清理；分页 | 直接以可读文件路径组织对象 | 保留 sol，避免同名覆盖直接破坏旧对象 |
| 文件操作 | 缺少覆盖与删除子目录 | 覆盖确认、子目录删除、可复用浏览组件 | 吸收完整操作；保留现有模块和 API，避免引入第二套文件浏览系统 |
| 工作组删除 | 会连带删除文件 | 有文件时拒绝删除、允许停用 | 采用 opus 的保护语义；字典替换导入也适用 |
| 并发编号 | 事务锁 + 持久计数器 | 事务锁 + 字符串 MAX | 保留 sol；超过 999 后仍正确递增 |
| PG 故障 | 部分依赖错误文本 | 按 PostgreSQL 异常类型、连接检查 | 采用 opus 的异常分类与借出检查 |
| SQL 初始化 | 自行按分号切割 | psycopg 原生执行 SQL 脚本 | 采用原生脚本执行，移除自制解析器 |
| 测试 | 有中心 HTTP 并发和存储审计 | 文件操作、启动、初始化专项更细 | 保留 sol 回归，补充融合行为与编号边界测试；历史成绩不作为新版本结果 |

新增文件写操作在所属标准 / 工作组上串行加锁，防止文件夹删除与上传交错。覆盖上传先写随机新对象，再更新元数据，提交后删除旧对象；回滚删除新对象。文件夹删除覆盖整个子树，按事务提交后清理对象。

单服务器仍保留 PostgreSQL 和 S3 的职责划分：现有业务已经使用该技术栈，无需重写存储层。它们可以与应用运行在同一主机。未引入分布式部署、消息队列、旧版本兼容或迁移。

原版中的浏览器业务署名不是身份认证。本版提供入口认证配置，但不扩展角色权限。PG 与 S3 之间仍无法跨系统原子提交；突然断电和对象删除失败可能留下孤立对象，用只读 storage_audit.py 检查并由管理员处理。

参考：psycopg 官方连接池文档 https://www.psycopg.org/psycopg3/docs/advanced/pool.html；Caddy 官方认证与反向代理文档 https://caddyserver.com/docs/caddyfile/directives/basic_auth 。实现前通过 Context7 核对了原生能力。
