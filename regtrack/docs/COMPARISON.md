# 标准比对使用说明（v21-fix3）

## 1. 启动与演示


本压缩包已包含初始化好的模拟演示库，进入 `regtrack` 目录后直接运行：

```bash
python -m pip install -r requirements.txt
python codes/run.py
```

若已经启动过而产生了空库，可另建演示库，不必删除任何已有数据：

```bash
python codes/init_db.py
python codes/run.py
```

进入“草案登记 → 标准比对”，选择“人形机器人 通用安全要求”，然后在“该标准已保存的比对”中点击讨论稿 1.2 → 征求意见稿 2.0，进入比对结果页。

本组原文、修订分析和批注均为功能演示用的模拟内容，不是正式标准文本，也不是实际法规结论。前版6条、后版9条，包含实质修改、拆分、编号调整、新增和未变化。

`examples/comparison-demo-result.xlsx` 是对应演示原文批次、已填写 Changes 的比对工作簿示例，不是可以导入任意草案的通用文件。该比对已经在演示库中保存；若要练习重新导入，先删除关联的模拟意见，再明确删除比对，随后上传示例文件。原文不会删除。

## 2. 正常使用流程

标准比对页签分两步，按顺序出现：

1. **选择比对版本**：在可搜索的下拉框中按编号或名称查找标准，再选择前版草案和后版草案。未导入原文的草案在下拉中显示为不可选。选好两版后系统立即校验：前版日期不得晚于后版（同一天的不同草案允许由用户明确指定方向），不通过时在此处提示原因；该版本对已有比对时直接显示“查看比对结果 →”，无需确认；尚无比对时点击“确认版本”进入第 2 步。该标准已有的比对列在下方，点击即打开对应的比对结果页。
2. **生成并导入比对结果**（该版本对尚无比对时出现）：
   1. 在“当前使用方法”中点击比对工作簿链接下载（单个 .xlsx 文件）。
   2. 复制页面上显示的提示词，与工作簿一起交给 Web 端大模型，下载模型返回的 Excel。也可以由人工填写同一工作簿。
   3. 上传返回的 Excel。选择文件后自动检查并显示预览（各修订性质数量与逐行说明），预览不写入数据库。核对后点击“确认导入”，保存后直接转到比对结果页。

### 比对结果页

地址为 `/drafts/comparisons/<id>`。布局与单版草案的章节阅读一致：左侧目录，右侧一次显示一个对应条目。左上角“返回”回到标准比对页签，并保持该版本对；也可“导出结果”或“删除比对”。

- **按修订性质浏览**：顶部页签为实质修订、编辑性修订、待核实、未变更、全部对应，并显示各自数量。首次打开停留在“实质修订”；之后记住上次选择。目录与右侧内容只包含当前页签下的条目。
- **目录**：可在“前版”和“后版”之间切换目录依据，并可按编号、标题或内容搜索。每个对应行只出现一次，位置和标题取该行在所选版本中的第一个章节；一行涉及多个章节时标题后显示“+N”。例如前版 C.5.3.5、C.5.3.5.1、C.5.3.5.2、C.5.3.5.3 对应后版 C.5.3.5、C.5.3.5.1、C.5.3.5.2，前版目录显示“C.5.3.5 … +3”，后版目录显示“C.5.3.5 … +2”。所选版本中没有章节的行（前版目录中的新增、后版目录中的删除）以“新增 / 删除”标注，排在上一行之后。点击条目在右侧打开；右侧顶部的 ‹ › 按目录顺序切换上一条、下一条。
- **条目内容**：自上而下为条目标题、修订性质与条款对应、修订分析（修订说明、判定依据、人工核实事项）、两版原文并排对照、比对批注。修订说明只在“修订分析”中显示一次。
- **修订标记**：前版中被删除或改动的文字显示为红色删除线，后版中新增或改动的文字显示为浅黄色高亮。拆分、合并、重组的多个章节合并比较。标题、正文和附图说明都会标记；表格、列表和公式按原样渲染，改动的公式整体加删除线或高亮。附图不做比较。
- **内容语言**：右侧顶部切换简体中文 / English，与单版草案阅读共用同一偏好。
- **附图**：点击缩略图在当前页小窗放大查看。
- **人工调整**：点击“编辑”可修改修订性质（实质修订、编辑性修订、待核实、未变更）以及中英文修订说明和判定依据。条款对应关系不可在此修改，如需调整请删除比对后重新导入。
  - “未变更”只能用于一对一、且两版编号、标题、正文、附图说明和附图数量一致的行；不满足时该选项不可选。选为“未变更”时修订类型同时改为未变更；从“未变更”改为其他性质时修订类型改为“修改”。
  - 改为“待核实”时必须填写人工核实事项。从“待核实”改为其他性质时，保存前会请用户确认移除人工核实内容。
- **批注**：每个条目下方可添加比对批注。批注保存后直接进入意见矩阵，来源为“多版本比对意见批注”；勾选需要跟进时初始状态为 Submitted，否则为 Draft（勾选框旁的 ⓘ 悬浮说明两者区别）。意见矩阵中的“查看比对条目”打开结果页，切到该条目所属的修订性质并显示该条目。

原文不自动发送到任何外部服务，请自行遵循组织的数据使用要求。“自动比对”目前仅说明接口未接通；系统没有接入模型接口、没有保存模型密钥，也不会自动翻译或自动生成语义修订结论。

## 3. 比对工作簿

确认版本后下载的单个 .xlsx 文件，文件名为 `标准号_前版v子版本_后版v子版本_比对工作簿.xlsx`。打开时默认位于 Changes 表。

| 工作表 | 内容 |
|---|---|
| Comparison | 系统元数据（标准、前后草案、原文导入批次），第2行不得修改 |
| Changes | 待填写的结果表，10列，见下节 |
| Before、After | 两版完整章节原文：Clause_no、Parent_clause_no、Level、Source_page、Title_cn、Content_cn、Title_en、Content_en、Illustration、Figures |
| Figures | 附图，每行一张，嵌入实际图片；Figure_id 与原文表 Figures 列对应 |
| Instructions | 字段填写规则 |

系统不会下载草案登记中的外部文件链接，工作簿只包含已经导入数据库的章节和附图。原文没有附图时 Figures 表只有表头，不会生成虚构图片。提示词只在页面显示和复制，不写入工作簿。

已保存比对的“导出结果”生成同样结构的工作簿，Changes 已填好，文件名以“比对结果”结尾。

## 4. Excel 契约

保留且只保留 Comparison、Changes、Before、After、Figures、Instructions 六张表，缺少或多出工作表时拒绝导入。提示词要求模型在原工作簿上直接写入 Changes 后另存，并在交付前重新打开核对六张表齐全。Comparison 的第2行是系统元数据，不得修改。导入只读取 Comparison 和 Changes；原文始终以数据库为准。

Changes 固定10列：

| 字段 | 填写内容 |
|---|---|
| Row_key | 唯一行标识，如 R001 |
| Before_clause_nos | 前版原始章节号，多个以英文分号分隔；无对应条款留空 |
| After_clause_nos | 后版原始章节号，多个以英文分号分隔；无对应条款留空 |
| Change_type | Unchanged、Added、Deleted、Modified、Moved、Split、Merged、Reorganized |
| Revision_class | Substantive、Editorial、Unchanged、Uncertain |
| Summary_cn | 具体变化的中文说明 |
| Summary_en | 中文修订说明的完整英文翻译 |
| Reason_cn | 修订性质的中文判定依据 |
| Reason_en | 判定依据的完整英文翻译 |
| Review_note | 人工核实事项；Uncertain 时必填，建议中英双语 |

两侧每个章节必须且仅覆盖一次，包括未变化项。拆分用一对多，合并用多对一，多对多重组用 Reorganized。一个条款内有多处变化时在同一行逐点写明，不重复章节引用。

最多10000个对应行，上传文件上限沿用系统的20MB。禁止公式。中英文说明和依据均必填。章节号必须在对应原文批次中真实存在，保留大小写、前导零和附录编号。

系统检查结构和引用，不会自动证明模型的技术判断或英文翻译正确。所有语义结论仍须业务人员复核。

## 5. 唯一源与数据保护

原文仍仅保存在 `draft_chapter` 和 `draft_chapter_image`。比对保存原文批次、章节对应关系及分析字段；页面每次从这些引用读取原文。结果 Excel 不包含第二份原文。

批注正文仅保存在 `comment`，`comparison_opinion` 只记录修订条目与意见的关联。意见矩阵和比对页共用同一记录，不是两份内容的定时同步。

- 同一前后草案对只保存一份比对，重复导入会被拒绝，不静默覆盖。
- 删除比对不删除原文。存在批注时必须先处理并删除关联意见。
- 原文被比对引用时不能重新导入替换，草案日期和所属标准也不能改动。先处理关联意见并删除比对，才能更换原文。
- 已下载工作簿与当前原文批次不符时拒绝导入，必须重新下载比对工作簿。
- 比对批注的标准、版本和章节来源绑定不可从意见矩阵改写，正文、类型和跟进状态可编辑。
- 用户数据交换包会携带必要原文和比对。若目标库已有不同原文，明确拒绝导入比对，不覆盖本机原文，也不把分析挂到不同原文上。

## 6. 提示词设计

提示词按“输入 → 输出文件 → 对应与覆盖 → 取值与判定 → 双语说明 → 交付前核对”的顺序，正面写明每一步应当怎样做。重点包括：

- 输出文件在上传的工作簿上直接填写 Changes 并另存（例如用 openpyxl 打开原文件），六张工作表随之完整保留；保存后重新打开核对六张表齐全。
- 数值、单位、否定、应/宜/可、适用条件和交叉引用的变化可能改变要求，按技术含义判定实质 / 编辑性修订。
- 附图不参与比对，也不列为待核实事项。比对依据为编号、标题、正文和附图说明文字；“未变更”要求附图数量一致，系统导入与人工调整按同一规则校验，不比较图片内容。
- 文字证据不足以判断时标记 Uncertain，并在 Review_note 写明需要人工核实什么。

## 7. 开发结构

- `codes/comparison_service.py`：版本和原文引用、覆盖校验、比对读取及数据交换校验。
- `codes/comparison_workbook.py`：比对工作簿（原文、附图、结果表）生成与结果读取。
- `codes/api/comparisons.py`：比对与批注接口。`GET /pair` 校验并确认版本对，`GET /workbook` 下载比对工作簿，`POST /preview`、`POST /import` 导入结果，`GET /<id>/export` 导出结果，`PUT /changes/<id>` 人工调整修订性质与说明（与导入共用 `comparison_service.check_analysis` 规则）。
- `templates/comparison_panel.html`、`static/js/pages/comparison.js`、`static/css/comparison.css`：草案登记中的标准比对页签（选择版本、导入）。标准下拉使用 `Fields.standard`（Tom Select，数据来自 `/api/standards/options`），与其他页面一致；`GET /api/comparisons/options?standard_id=` 只返回该标准的草案及章节数。
- `templates/comparison_detail.html`、`static/js/pages/comparison-detail.js`、`static/css/comparison-detail.css`：比对结果页，沿用 `draft-reader.css` 的阅读框架（draft-context、draft-view-tabs、reader-column、reader-scroll、reader-language）。
- `static/js/revision-diff.js`：修订标记。按词（中文按字）切分，用 jsdiff（`static/vendor/diff.min.js`）比较；公式、行内代码和链接作为整体，Markdown 结构符号（行首标记、表格竖线与分隔行、强调符号、HTML 标签）不包裹，保证表格和公式照常渲染。
- `static/js/rich-text.js`：Markdown + KaTeX 渲染，草案章节阅读和比对结果页共用。
- `static/draft-comparison-prompt.txt`：单一提示词文件，页面显示与复制使用。
- 步骤面板沿用 `static/css/draft-reader.css` 中导入页的 step-number、import-choices、import-guide、import-actions 样式。
- `codes/test_comparisons.py`：接口、导入、引用、批注及交换回归用例。
