# 法规跟踪系统 · 使用说明

给日常录入和查询的同事。不需要懂编程。

---

## 一、第一次使用

### 1. 直接运行发布版（推荐）

Windows 用户直接双击 `release/RegTrack.exe` 即可。首次启动会自动完成全部前置工作，
在 exe 同级的 `data\regtrack-v0.19-fix3.db` 创建空数据库；不需要运行 `init_db.py`，也不会加载初始化记录。

### 2. 从源码运行（开发机）

到 <https://www.python.org/downloads/> 下载安装。
**Windows 安装时务必勾选 "Add Python to PATH"**，否则后面命令会提示找不到 python。

打开命令行，进入本系统目录：

- Windows：在 `regtrack` 文件夹地址栏输入 `cmd` 回车
- macOS：在 `regtrack` 文件夹上右键 →「服务」→「新建位于文件夹位置的终端窗口」

然后执行：

```
pip install -r requirements.txt
python codes/fetch_vendor.py  # 仅源码运行且 static/vendor 缺失时执行
python codes/run.py           # 首次启动自动创建空库
```

如果执行了 `fetch_vendor.py`，该步骤要联网（下载页面样式文件），**只需要执行这一次**，之后断网也能用。
最后一条执行完，浏览器会自动打开系统首页；如果没自动打开，
手动访问 <http://127.0.0.1:5000>。

### 3. 以后每次使用

只要最后一条：

```
python codes/run.py
```

**命令行窗口不能关**，关掉系统就停了。用完在窗口里按 `Ctrl + C` 停止。

---

## 二、开始之前

生产发布版默认没有任何业务数据。`sql/seed.sql` 是开发验证用的标准主档与内部跟踪初始化记录，
不要在用户端执行初始化脚本；如需在开发环境加载初始化记录，再执行：

```
python codes/init_db.py --force
```

进入系统后，当前操作人显示在左下角；如需变更，请进入左侧「设置」→「切换操作人」，选择后确认“确认切换操作人账户为 xxx 吗？”。所有记录的「记录人」都取当前账户。

## 三、五个主入口

左侧导航的编号与《Forms 与 Subforms 设计说明》一致。

### 1. 标准主档 Standard Profile

一项标准建一条，是全系统的中心。必填：标准号、中文名称、起始阶段。

建档时只要登记**现在所处的阶段**就行，更早的阶段随后可以补录。TC/WG、责任单位、
牵头单位、负责人、影响领域这些字段，**即使字典里还没有这个值，直接输入就能保存**，
系统会在保存标准的同时把新值写进字典，下次别人就能直接选到。保存失败时页面会直接
说明是哪一项、为什么不行（例如标准号重复、日期格式不对），不会只给一句网络错误。

打开明细后，顶部是**阶段时间轴**，九个阶段（预研 → 立项 → 起草 → 征求意见稿 →
送审稿 → 报批稿 → 发布 → 实施 → 废止）走到哪一格一眼可见。下方六个页签汇总了
这项标准的阶段历史、草案、会议、意见、事项，不用再去别的页面翻。

**推进 / 补录阶段**：点右下角的「推进 / 补录阶段」，在「目标阶段」里选要记录的阶段。

- 选**当前阶段之后**的阶段 → 正常推进，生效日期不能早于当前阶段的日期。
- 选**当前阶段之前、还没填过**的阶段 → 自动进入历史补录模式，弹窗顶部会提示
  「⚠您正在补充更早阶段信息，请注意外部审计规范性」。补录可以填**真实发生时间**，
  不受当前阶段的时间顺序限制。例如标准已经在「起草」阶段，仍然可以把「预研」和
  「立项」的信息补齐。补录不会改变当前阶段。

阶段记录会标明来源是**正常推进**还是**历史补录**。每条记录都会显示两个时间：
**创建时间**（第一次记下这个阶段的时间和人）和**最近修改时间**（最后一次改动的时间和
改的人，没改过就显示「未修改过」），审计追溯看这两行即可。点时间轴上任意一段看详情：

- 已填写的阶段**都可以改**，不分推进还是补录：详情里的「修改」入口可以更正生效日期、
  依据和补充说明。阶段本身不能改写——记错了阶段就另填一条记录。
- 每改一次，「最近修改」会刷新成这次的时间和操作人，创建时间始终保持第一次记录时的值。
- 当前阶段之前尚未填写的阶段，详情里有「补录该阶段」入口。

编辑标准主档时看不到可改的「当前阶段」字段，只会显示当前值并提示
「阶段信息请通过推进/补录阶段功能调整」——当前阶段由阶段记录自动算出，
这样谁也绕不过阶段管理直接改生命周期状态。

**归档代替删除**：明细左下角的按钮是「归档」而不是「删除」。归档后这项标准不再出现在
标准列表、下拉框和总览统计里，但标准主档、阶段历史和全部关联记录都完整保留；
在标准列表勾选「查看归档」就能找回来，点「恢复」即可回到正常列表。

### 2. 草案登记 Draft Registry

一个版本一条：征求意见稿、送审稿各自是一条草案。必填：所属标准、版本名称、
子版本号、草案日期。版本名称只能从下拉中选择：立项草案、讨论稿、征求意见稿、
送审稿、报批稿、发布稿、修改单。

在「草案版本管理」可先上传章节 Excel，再确认属于哪个标准和草案版本；没有对应版本时可新建。
确认后进入独立草案详情，左侧目录与正文、右侧批注分别滚动。整份草案批注在概览页。
再次导入已有章节时，先选择内容冲突的批注是否改用新导入内容，再选择新文件没有批注的旧条目是否保留。相同内容自动沿用；新文件已删除的条款批注会移除。已关联本草案、且条款编号被新文件删除的正式意见也会在最终确认后删除，确认框会说明数量与编号。若批注或关联意见在选择后被其他页面修改，系统会要求重新核对。每个条款最多一条批注。Excel 初始批注和之后新增的批注采用同一数据库字段与编辑方式，均可在页面内直接编辑，并显示创建与修改时间；切换章节前若有未保存的编辑，可选择保存、放弃或继续编辑。
「标准比对」目前是空白占位页签。

要登记的标准还没建档？在表单里的标准下拉框搜不到时，直接点下拉框底部固定的「快速建档」，
建完自动回到当前表单并选中，不用中断手上的活。

### 3. 工作组会议 WG Meeting

必填：会议名称、会议日期。会议号（`MTG-2026-001` 这种）系统自动生成。

**一场会议可以同时挂多项标准**：联合协调会、内部月度例会这类会议往往一次讨论好几项标准，
登记或编辑会议时在「涉及标准」里逐个选上即可；也可以先不挂，之后在会议明细里用
「挂上标准」追加、用「移除」去掉。同一项标准也可以出现在多场会议里，互不影响，
在标准明细的「会议」页签能看到它参加过的全部会议。

**每项标准可以单独写「本会批注」**：一场会往往要过好几项标准，各自的议论分开记，
才不会糊成一段会议纪要。在会议明细的「涉及标准」行尾点「添加批注 / 编辑批注」即可，
批注会显示在标准名称下方，会议列表里也看得到。批注属于「这场会 × 这项标准」这条挂载
关系——同一项标准在别的会议上是另一条批注，互不影响。
**取消挂载会把批注一并删掉**，所以移除写过批注的标准时会先提示
「您正在取消挂载一份批注过 Note 的标准，如确认移除，Note 也将丢失。」，确认后才执行；
在编辑会议的多选框里取消勾选同样会先问一句。

会议明细里的「涉及标准」表格，每一行右侧有**五个派生按钮**：

`+ Survey Feedback`　`+ Collect Comments`　`+ Lobby with Drafter`　`+ Compliance Check`　`+ Others`

点任意一个，直接弹出对应类型的事项表单，**会议号、会议名称、标准号、标准名称已经带好**；事项类型在进入表单后固定，需改类型时退出后重新选择入口。只需要补充该类型自己的字段。

### 4. 意见矩阵 Comment Matrix

必填：所属标准、意见内容、理由依据、意见状态、提出人。
选定标准后，草案下拉会自动只显示该标准下的版本。

意见状态（Draft / Submitted / Accepted / Partially Accepted / Rejected /
Pending / Withdrawn）的推进方式与标准阶段相同：点「更新状态」，只填新状态和生效日期，
历史自动留痕。

### 5. 事项 Action Item

五个类型：Survey Feedback（征集反馈）、Collect Comments（收集意见）、
Lobby with Drafter（与起草方沟通）、Compliance Check（合规检查）、Others（其他）。

点「新建事项」会先展开五个类型入口；选定后直接进入相应表单，类型固定不允许在表单内切换，不用面对一大堆用不上的空格。
除 Others 外都必须关联标准。

**Collect Comments 类型带「反馈对象」子表**：列出要向谁征集意见、要求何时回复。
对方回复之后，在反馈对象那一行点 **「+ 生成 Comment」**，系统会带着标准、草案、
提出人等信息跳到意见矩阵的新建表单，补上意见正文即可。同一条反馈重复点，
系统会提示已经生成过并直接带你去看那条意见。

## 四、几个好用的地方

- **按标准查看相关工作**：草案版本、意见和事项都按标准集中成组，首次进入
  默认全部展开。点击蓝色标准标题行可单独收起或展开，筛选区右侧也有「全部展开」和
  「全部收起」。搜索或筛选后，只显示符合条件的记录并自动展开结果；最新登记了记录的
  标准排在最上方，同一标准内也按系统登记时间从新到旧排列。
- **总览页 · 登记概览**：计数之后是标准阶段分布（横向细柱，九个阶段从预研到废止依次
  列出，没有标准的阶段也会占一行显示 0）和意见采纳情况（环形图，悬停图例可看各状态
  明细）。再往下是两块清单，都按人过滤，**默认就是顶栏选定的当前操作人**：
  - **在办事项 · 按截止日期**：逾期的会标红。右上角的「登记人」可以换人，
    也可以选「不限」看全部。
  - **今年已参加的工作组会议**：默认是今年 1 月 1 日到今天。右上角可以换参会人、
    改起止日期，「今年」按钮一键回到默认区间。这里的「参加」按两条线算：
    会议的参会人员里写了这个人，或者这场会是这个人登记的——参会人员是自由文本，
    写法不一定统一，两条线一起算才不容易漏。

  每天先看这一页。
- **总览页 · 标准生命周期回顾**：选择一个标准，以泳道式时间轴回顾它的制定过程。
  - **链条即骨架**：横向的生命周期链上，每个阶段节点下方直接挂载该阶段的会议、草案和
    意见卡片，像吊牌一样沿节点的吊线垂下。节点上显示阶段起止日期、历时，以及会（会议）、
    稿（草案）、意（意见）的数量。
  - **链条固定**：看板铺满屏幕剩余高度，向下滚动时链条始终固定在顶部；列多时可横向滚动，
    链条与各列保持对齐。窗口或面板变窄时，工具栏、概况卡和列宽会自动重排。
  - **沉浸查看**：工具栏上的「沉浸查看」把看板铺满整个窗口，按同一个按钮或 Esc 退出。
    沉浸状态下照样能点开会议、草案、意见的详情弹窗。
  - **一眼看出阶段状态**：已经历的阶段为实线，历史补录进来的阶段会标注「历史补录」；当前阶段整列浅蓝底色并标注「当前」（废止为
    红色）；尚未进入的阶段为灰色虚线细列；被跳过的阶段不显示，「废止」只有真正发生后才
    出现。没有记录的阶段自动收窄，只显示「无记录」。
  - **概况卡**：顶部显示标准编号、类型、风险等级与影响领域，右侧是制定进度条和会议、草案、
    意见数量及意见采纳率（已答复意见中采纳与部分采纳的占比）。「标准主档」和「导出 Markdown」
    按钮在选择框右侧。
  - **意见卡片**：左侧色条和右上角标签表示结果（绿=采纳、黄=部分采纳、红=不采纳、蓝=进行中、
    灰=已撤回，悬停标签可看原始状态），卡片显示编号、条款与主题和两行摘要。点击卡片展开全文和起草组回复，
    再点「详情」打开完整记录；会议和草案卡片点击直接打开详情。每列默认显示前 8 条意见，
    其余点「显示其余」。
  - **意见筛选**：链条上方可按结果分类筛选，或按编号、条款、主题、内容搜索；对所有阶段
    同时生效，节点上的「意」徽标同步显示命中数。
  - 归档规则：草案按版本名称对应的阶段归档（讨论稿→起草、发布稿→发布等），该阶段未经历
    或是修改单时按草案日期归档；意见跟随其关联草案，未关联草案的按提交日期归档；会议按
    会议日期归档。
  - 「导出 Markdown」会把该标准的全部历史（含草案章节与事项）按固定模板生成 .md 文件，
    便于留存和放入知识库。当前标签和所选标准会写进网址，刷新或把链接发给同事都能回到
    同一视图。
- **下拉框都能搜、也能现场新增**：字典类下拉（TC/WG、人员、机构、团队、影响领域）
  直接输入没有的值即可，保存这条记录时新值会一并写进字典；标准可以按标准号或名称搜；即使没有匹配项，下拉框底部固定有「快速建档」按钮，建完会自动回选。选项里还会顺带显示当前阶段、
  TC/WG、负责人、草案数，选之前就能确认没选错。
- **操作人数据交换**（设置页）：按登记人导出的包是自包含的——他的事项挂在别人建的标准上时，
  那条标准会一并带出来，对方导入后不会出现「事项找不到标准」。
  **导入分两步**：选好文件后先弹出确认框，显示数据包的登记人和各类记录条数，
  再让你确认这批数据记到哪位操作人名下——本机已有这个人就选它，没有就当场新增。
  同一个人写成「Wang, Xuesong」和「王学松」时请选同一条，否则会在本机分裂成两个操作人，
  统计和筛选都会对不上。确认后才真正写入：
  - 导入时**重新编号**。两台电脑各自从 1 开始编号，对方的「标准 1」和你的「标准 1」
    本来就是两回事，所以不保留原 id。
  - **同一条记录自动合并**：标准编号、草案版本、字典值、同一天的同名会议若本机已有，
    就沿用你的那条，不会重复建档。若本机草案已有章节，其章节与批注以本机为准，
    导入包的对应内容会跳过并计入结果；本机无章节时可导入来源的当前章节。
  - **业务编号冲突时重新取号**：导入的事项号、意见号若和本机的撞上，系统重新发号，
    不会顶掉你的记录。
  - 导入完成后会报「新增 / 合并 / 跳过」三个数字；有跳过的记录会弹出逐表明细和原因。
- **设置**：在「切换操作人」中变更当前登记账户；在「字典维护」中维护影响领域、人员、团队、机构、TC/WG。
  标准阶段不在字典里维护——它由系统按固定编码管理，名称由界面统一展示。每个字典主题都可单独导入/导出，导入支持补充或完全替换；补充时若排序冲突，需修改排序后重新导入。列表中的排序数字可直接批量编辑并保存。
  停用的项不再出现在下拉框里，但不影响已有记录。填表时在下拉框里直接输入新值
  也能就地添加。
- **沿业务方向查看关联记录**：在标准里点草案 / 会议 / 意见 / 事项、在会议里点派生事项、
  在事项里点生成的意见，都会在当前窗口上再叠一层，不会切换到别的主入口。
  标准、会议、草案等来源信息在子记录里只展示，不再反向跳转，因此不会循环打开同一批记录。
  标题栏左上角有「返回」按钮，副标题显示走过的路径；悬浮按钮仍会提示返回目标
  （如 `MTG-2024-001 › AI-2024-001 › CM-2024-001`）。点击返回、取消或弹窗外背景
  都只关闭当前层。弹窗打开期间，浏览器后退键不会关闭弹窗或离开系统，页面会提示使用
  弹窗内的返回或取消；全部弹窗关闭后，浏览器后退恢复正常。Esc 不关闭弹窗。
- **编辑后仍回到原详情**：编辑表单叠在详情之上。保存会刷新下面的详情，取消、返回或
  点击弹窗外背景会直接回到原详情，不会多退一层。阶段或状态更新成功后也会自动回详情。
- **小窗口可拖动**：按住标题栏即可把窗口拖到屏幕任意位置，拖动过程中窗口尺寸不变；
  拖过头也不会丢——标题栏始终留在屏幕内，双击标题栏可一键复位。叠起来的窗口会
  依次错开，方便看出下面还压着哪一级。
- **下拉选项框浮在窗口之上**：展开时不会把窗口撑大，也不会被窗口边缘裁掉；
  下方空间不够时自动向上展开，选项多时面板内部自己滚动。
- **想让同事也能用**：改成 `python codes/run.py --host 0.0.0.0` 启动，
  同一局域网内的同事用 `http://你的IP:5000` 就能访问。数据都在你这台机器上。

## 五、遇到问题

| 现象 | 处理 |
| --- | --- |
| 提示 `python 不是内部或外部命令` | Python 没装或安装时没勾 "Add Python to PATH"，重装一次 |
| 提示找不到数据库 | 正常启动会自动创建；确认 exe 同级目录可写，并重新双击启动 |
| 页面能打开但样式很乱、下拉框不能搜 | 联网执行一次 `python codes/fetch_vendor.py` |
| 提示端口被占用 | 换端口：`python codes/run.py --port 8080`，然后访问 `http://127.0.0.1:8080` |
| 右下角弹出「初始化失败」 | 先按 `Ctrl + Shift + R`（Mac 用 `Cmd + Shift + R`）强制刷新，清掉浏览器缓存的旧脚本；仍不行则确认命令行窗口里的服务还在运行 |
| 想让某项标准不再出现在列表里 | 打开明细点「归档」；数据不会丢，勾选列表上方的「查看归档」还能找回并恢复 |
| 想清空所有数据重新开始 | 停止系统后删除 exe 同级的 `data\\regtrack-v0.19-fix3.db`，再重新启动（**数据会全部删除**） |

**备份**：v0.19 数据保存在 `data/regtrack-v0.19-fix3.db`。
系统停止后把它复制一份就是完整备份；要恢复，把备份文件覆盖回去即可。
建议定期复制到网盘或移动硬盘。
