先看全貌

你电脑上有一份 RegTrack 代码；GitHub 上也有一份。你可以在电脑上修改，保存成一次“提交”，把提交上传到自己的分支，然后请 GitHub 把它合并进正式分支。

电脑上修改→提交 commit→上传 push→申请合并 PR→正式分支更新

这里的“合并”不是把两个文件夹粗暴覆盖，而是让 Git 记录哪些内容发生了变化，并把选定的变化加入目标分支。

以你的仓库为例

仓库

01RK/regtrack：GitHub 上存放项目代码和历史记录的地方。

正式分支

regtrack/0.18.0：目前完整源码所在的分支。本教程中的 PR 都以它为目标。

临时分支

例如 feature/improve-readme：做某一项修改时使用，完成后再合并。

当前仓库有一个特别之处：GitHub 默认显示的 main 目前只有初始 README；完整源码在 regtrack/0.18.0。浏览仓库时请先切换到这个分支。由于最初上传方式特殊，首次在电脑上继续开发之前，还需按第 3 页做一次本地对齐。

学习路线

  1. 第 2 页：理解仓库、分支、提交、推送、拉取和 PR。
  2. 第 3 页：一步一步在电脑上改一处内容并上传。
  3. 第 4 页：在 GitHub 上检查差异、创建 PR、合并。
  4. 第 5 页：遇到冲突、登录问题或误操作时怎么处理。
