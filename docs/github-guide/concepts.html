第 2 课

先把几个词说清楚

把 Git 想成“记录文件变化的工具”，把 GitHub 想成“存放这些记录并协作的网站”。

六个最常用的概念

词通俗解释在 RegTrack 中的例子
仓库 repository一个项目的文件及其修改历史01RK/regtrack
本地 local你电脑上的那份仓库你正在编辑的项目目录
远程 remoteGitHub 上的那份仓库；通常叫 origingithub.com/01RK/regtrack
提交 commit给一组改动拍一张有说明的快照“完善安装说明”
分支 branch从某个提交出发，独立继续修改的一条线路feature/improve-readme
拉取请求 PR请人检查并把一条分支合并到另一条分支的申请从 feature 分支合并到 regtrack/0.18.0

为什么要有分支？

假设正式版本是一篇已经交稿的文章。你想改安装说明，可以先复制出一条“修改线”，在上面尝试。正式分支继续保持当前状态。检查完改动后，再把修改线的内容合并进去。

regtrack/0.18.0 正式分支↘feature/improve-readme 修改分支→PR 检查→合并回正式分支

分支名只是标签。feature/ 是常见命名习惯，Git 不要求必须这样写。

几组容易混淆的动作

保存文件 ≠ 提交

保存只是改电脑上的文件。git commit 才会把选中的改动写入 Git 历史。

提交 ≠ 上传

提交先存在你电脑里。git push 才会把它发到 GitHub。

上传 ≠ 合并

上传 feature 分支后，正式分支仍未改变。PR 合并后才改变。

拉取 pull

git pull 把 GitHub 上较新的提交取回电脑，通常在开始工作前使用。

记忆句：先拉取最新版本，再建分支修改；提交记在本地，推送传到 GitHub；最后用 PR 合并。
