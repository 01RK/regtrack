从电脑上完成第一次修改

下面用“修改 README 的一句话”为例。每个命令都在仓库根目录运行，即有根目录 README.md 的地方。

第一次使用：先对齐本地与 GitHub

RegTrack 最初通过 GitHub 接口上传，电脑上的提交历史与 GitHub 上的历史不同。以下步骤只需做一次。

1
确认没有未提交的改动
git status

如果看到 working tree clean，继续。若列出 modified 或 untracked 文件，先保存并确认这些改动怎么处理，暂时不要执行第 3 步。

2
备份旧历史，取回 GitHub 的记录
git branch backup/local-0.18.0
git fetch origin

备份分支像书签。fetch 只下载远程记录，不改当前文件。

3
把本地发布分支对齐到 GitHub
git switch -C regtrack/0.18.0 origin/regtrack/0.18.0

这会切换工作目录中的文件。只有第 1 步确认工作区干净后才执行。若报错，先停下查看错误。

这里的 -C 只用于一次性对齐已有分支。平常新建功能分支使用小写 -c。

每次修改：照着这七步做

  1. 更新正式分支
    git switch regtrack/0.18.0
git pull origin regtrack/0.18.0
  2. 创建本次修改专用分支
    git switch -c feature/improve-readme

    如名字已经用过，可换成 feature/readme-setup-2026。

  3. 用编辑器修改根目录 README.md 并保存。
  4. 检查改动
    git status
git diff

    status 看文件列表，diff 看具体改了哪些行。

  5. 选择文件并提交
    git add README.md
git commit -m "完善安装说明"
  6. 上传自己的分支
    git push -u origin feature/improve-readme

    首次上传可能需要在浏览器完成 GitHub 登录。不要在聊天里发送密码或访问令牌。

  7. 去 GitHub 创建 PR，接着阅读下一页。

为什么要分成这些动作？

命令含义
git switch切换当前工作分支
git pull把 GitHub 上的更新带到本地
git add挑选本次要提交的文件
git commit保存一条本地历史记录
git push上传本地提交到 GitHub
