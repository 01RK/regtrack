第 5 课

遇到问题时先看这里

Git 报错通常是在保护已有改动。先读报错，再用 git status 确认当前状态。

常见情况

我改了文件，但 GitHub 上看不到

检查是否依次执行了 git add、git commit、git push。如果推送了 feature 分支，GitHub 默认展示的分支未必是它；切换分支或打开 PR 查看。

git pull 提示本地改动会被覆盖

先执行 git status 看文件名。需要保留的改动先在当前分支提交；不确定时先把文件另存一份。不要直接运行 git reset --hard。

PR 说不能自动合并，有冲突

说明两条分支改了同一位置。先在 PR 中看冲突文件，理解两边各改了什么；小型文本冲突可用 GitHub 的 Resolve conflicts 页面选择最终内容。涉及代码逻辑时先确认程序应该保留哪种行为。

git push 要求登录，或提示 Authentication failed

按终端或浏览器提示完成 GitHub 登录。如果终端无法弹出登录界面，可使用 GitHub Desktop 登录后上传，或检查电脑上的 Git Credential Manager。不要在聊天、截图或仓库中粘贴令牌。

GitHub 上只看到 README，看不到源码

页面左上方分支菜单默认可能显示 main。切换至 regtrack/0.18.0。

安全习惯

  • 每次提交前看 git status 和 git diff。
  • 数据库、密钥、个人资料不要加入 Git；留意 .gitignore。
  • regtrack/sql/seed.sql 是公开的虚构示例数据；不要把真实业务数据写进去。
  • python codes/init_db.py --force 会重建本地数据库，与 Git 合并无关；它可能删除现有本地数据。
  • 一个 feature 分支尽量只做一件事，PR 更容易检查。

随手速查

git status                         # 看当前状态
git branch --show-current          # 看当前分支
git diff                           # 看具体改动
git switch regtrack/0.18.0        # 回到发布分支
git pull origin regtrack/0.18.0   # 获取最新版本
git switch -c feature/名字        # 创建修改分支
git add 文件名                    # 选择文件
git commit -m "说明本次修改"      # 保存提交
git push -u origin feature/名字   # 首次上传分支
完整流程：理解概念 → 本地修改 → 提交 → 上传 → PR → 合并 → 更新本地。以后重复第 3、4 页的日常步骤即可。
