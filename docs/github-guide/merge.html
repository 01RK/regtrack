第 4 课

在 GitHub 上检查并合并

上传 feature 分支后，还需要用 Pull Request（简称 PR）把它并入发布分支。

创建 PR 的操作

  1. 打开 01RK/regtrack。上传后页面通常显示 Compare & pull request；点它。如果没有，进入 Pull requests → New pull request。
  2. 核对分支：base = regtrack/0.18.0，compare = feature/improve-readme。base 接收修改，compare 提供修改。
  3. 写标题和说明。标题可写“完善安装说明”；说明写清楚改了什么、为什么改。点击 Create pull request。
  4. 打开 Files changed，逐行看变化。绿色是新增，红色是删除。确认没有误传数据库、密码或无关文件。
  5. 确认后点击 Merge pull request，再确认。此时 regtrack/0.18.0 才真正收到修改。
GitHub 可能预设 main 为 base。你的完整源码目前在 regtrack/0.18.0，务必把 base 改成它。

合并后，电脑上还要更新

GitHub 已合并，但电脑上的正式分支还在旧位置：

git switch regtrack/0.18.0
git pull origin regtrack/0.18.0

确认更新成功后，可删除已经完成的本地临时分支：

git branch -d feature/improve-readme

PR 页面也可能出现 Delete branch 按钮；确认合并成功后可以删除远程临时分支。

PR 创建后又想修改怎么办？

回到同一条 feature 分支继续编辑、提交、推送，已有 PR 会自动显示新提交。

git switch feature/improve-readme
git add README.md
git commit -m "补充运行环境说明"
git push

只改一两个文字时，也可以在 GitHub 网页点击文件旁的铅笔图标编辑，创建新分支并提出 PR。
